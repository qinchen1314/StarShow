# Prove-It 实证验收门禁 Skill

## 核心铁律（无实证，不完工）

**严禁仅凭“代码已写完”“`mvn compile` 通过”或口头推断宣称任务完成。**
每一次交付都必须用**现场实跑的命令结果、可复现断言、真实 `git diff` 审计与运行态证据**来证明代码确实按预期工作。

## 触发条件

- 完成任何功能开发、架构重构、Lua/SQL 修改或 Bug 修复后；
- 准备执行 `git commit`、打里程碑 Tag（`v0.2.0-chain1` ~ `v1.0.0-release`）或提交 PR 前；
- 用户要求“验收一下”“prove it”“证明没问题”“跑测试检查”时。

## 四步强制验收流水线

### 第一步：实跑对应层级的真实测试（拒绝用旧缓存结果充数）

根据本次改动涉及的风险面，按下面 **4 级验收矩阵** 现场执行实测：

| 验收级别 | 适用场景 | 必须实跑的验证内容与硬性断言 |
| --- | --- | --- |
| **L1 单元与不变量证明** | 任何代码改动（必选） | 运行 `mvn -B test`（或目标模块 `-pl <mod> -am test`）；校验核心不变量（基因位精准路由、状态机禁 `CLOSED` 复活、AES-GCM 篡改失败、Redis Key `{showId}` Hash Tag 一致性） |
| **L2 并发与零超卖证明** | 涉及链路二/三库存、座位、锁、Lua、分表 | 实跑并发测试（如 200+ 线程并发抢 20 张票 / 并发抢同一连座），必须输出并断言：`Redis已扣数 == DB有效订单数 <= 初始总库存`、`同一(user_id, show_id)最大有效单 == 1`、**超卖数 = 0、重复单 = 0** |
| **L3 魔鬼故障剧本证明** | 涉及事务消息、支付回调、关单、退款 Saga、对账 | 按需实跑并验证故障剧本：① 事务 Commit 丢包 → Broker 回查 `deduct_log` 自动补单；② 回查先 `ROLLBACK` 写墓碑 → 延迟 Lua 返回 `-3` 零悬挂；③ `?fault=DUPLICATE_3X` 连发 5 次回调 → 只出 1 张票；④ `?fault=DROP_CALLBACK` 丢回调 → 关单任务主动查单补票不误关；⑤ `?fault=RACE_WITH_CLOSE` 关单后滞后回调 → 绝不复活订单并自动生成异常退款单；⑥ 注入 1 笔账目差异 → 对账任务精准写入 `t_reconciliation_diff` |
| **L4 压测真实性证明** | Phase 5 V1→V4 对比压测 | 必须使用同一套 5,000+ 独立用户 JWT Token 池；记录本机硬件与 JVM 参数；V4 必须同时给出 **API 受理 TPS/P99** 与 **MQ E2E 落库排空总耗时（Drain Time）**，且压测后自动运行 DB+Redis 一致性对账断言全通过 |

### 第二步：防测试弱化与 `git diff` 完整性审计

必须实际执行 `git diff`（或 `git diff --cached`）并重点审计两件事：

1. **禁止弱化测试（Anti-Test-Weakening）**：
   - 检查所有变更的 `*Test.java` 文件，确认**没有**为了“让测试变绿”而删掉断言、注释 `@Test`、调低并发线程数、把异常吞掉、或把关键真实路径替换成恒为真的假 Mock。
   - 若确实修改了既有测试，必须在验收回执中明确说明修改原因并证明新断言不弱于原断言。
2. **禁止隐性违规**：
   - 确认没有把调试日志、硬编码临时开关、或未处理的 `TODO` 带入主逻辑。

### 第三步：运行态与开源脱敏验证

- **运行态端到端抽检**（当改动涉及 HTTP API、Docker Compose、SQL DDL 或 Lua 时）：
  - 优先在真实运行环境（Docker 中间件 / Testcontainers / SpringBootTest）走通至少一条完整请求链路（如 `curl` / MockMvc / 真实 Redis 执行 Lua 返回码校验），而非只看单元测试 Mock。
  - 若当前本机 Docker 未启动导致集成测试无法连接真实中间件，**必须如实标明“集成实跑受限于 Docker 未启动”**，绝不允许伪造通过。
- **GitHub 提交前脱敏扫描**：
  - 扫描待提交变更，确认零真实密码/密钥、零个人真实邮箱、零本机绝对路径、零代理配置泄露，且 `.env` 未被跟踪。

### 第四步：输出结构化《实证验收回执》

禁止只回复一句“已完成”或“测试通过”。必须附带以下简洁回执（无废话、只列事实与证据）：

```markdown
### Prove-It 实证验收回执
- **验收级别**：L1 / L2 / L3 / L4
- **实跑命令与结果**：`<实际执行的命令>` → `Tests run: X, Failures: 0, Errors: 0`（附关键并发/剧本实测指标）
- **运行态证据**：<真实接口返回 / Lua 返回码 / DB 核对断言，或如实说明环境受限项>
- **Diff 防弱化审计**：已检查 `git diff`，确认未删除/弱化任何既有测试断言
- **脱敏与仓库卫生**：已扫描待提交变更，0 敏感密钥/本机路径/真实邮箱泄露
- **剩余缺口（诚实声明）**：<若无则写“无”；若有未覆盖的集成/压测场景必须明确列出>
```
