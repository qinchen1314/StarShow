# 板块开发设计规格书标准模板（Design-First 规范）

在启动任何新链路或大型板块编码前，**必须先按本模板调研行业成熟方案并补全对应的 `docs/domains/0x-*.md`**，经评审拍板后再动工。

## 强制 7 大章节结构

每份板块开发规格书必须包含以下 7 个章节（缺一不可，杜绝空话）：

1. **成熟方案调研与化用决策（不重复造轮子）**
   - 明确列出本板块涉及的核心技术点、行业成熟组件/模式、我们直接复用的现成能力，以及刻意规避的反模式与踩坑点。
2. **全链路全景时序与节点拆解**
   - 使用 Mermaid 时序图或流程图画出端到端调用链（入口 → 网关/过滤 → 业务节点 → 存储/缓存/MQ → 异步消费），并将链路拆解为清晰的编号节点（节点 0、节点 1……）。
3. **各节点详细业务内容与技术实现**
   - 每个节点必须写明：**业务目标、输入/输出、核心校验规则、精确技术手段（类名/包路径/SQL/Lua/Redis/MQ API）、幂等与并发处理**，做到“拿文档即可直接写代码”。
4. **精确契约与模块变更清单**
   - 列出涉及的 REST API 路径与错误码、MySQL 表/索引、Redis Key、MQ Topic/Event Schema、新增 Maven 依赖及 `starshow-api` 新增 Facade/DTO。
5. **异常边界、并发竞态与降级策略**
   - 显式列出高并发竞态（如 TOCTOU 唯一键冲突）、中间件抖动（Redis/MQ 异常）、边界时间（如已开票后预约）及对应降级/补偿动作。
6. **跨板块影响矩阵（上游依赖 / 下游暴露 / 共享底座）**
   - 清晰说明本板块对其他 3 个业务板块、`starshow-common`、`starshow-api`、`starshow-gateway`、后续压测（Phase 5）与演示台（Phase 6）的影响与接口解耦方式。
7. **Prove-It 实证验收清单**
   - 逐条列出可执行的 L1 单元测试用例、L2/L3 集成与故障剧本、运行态接口验证步骤及明确断言，确保动工前验收口径 100% 量化。
